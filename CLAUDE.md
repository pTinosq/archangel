# Archangel

AI agent that operates a real Android phone and a Windows PC. No cable, ADB or root at runtime. Progress: `docs/roadmap.md`.

```
channels ⇄ gateway ⇄ orchestrator ──▶ tasks ──▶ pilots ──▶ relay ◀──WebSocket── bridges (phone, PC)
 (any medium,  (events in,  (one conversation,  (background     (action)
  one owner)    routing out)  kept as threads;    sub-agents)
                              talks, manages)
```

## Layout

| Path | What |
|---|---|
| `apps/agent/` | Python, Pydantic AI + uv. Channels, gateway, orchestrator, tasks, device pilots (phone, PC). |
| `apps/bridge/` | Android bridge, Kotlin. AccessibilityService that dials the relay and runs commands. |
| `apps/bridge-windows/` | Windows bridge, Python, built into an exe by CI. A service that dials the relay and runs commands, the lock screen included ([README](apps/bridge-windows/README.md)). |
| `apps/relay/` | Python relay, FastAPI + uv. Holds device connections, exposes the HTTP API. |
| `apps/panel/` | Control panel, React + Vite + plain CSS. Pages at real paths (`route.tsx`; the agent serves the app on each, `web.PAGES`): `/chat`, `/tasks` (what's scheduled above the tasks, each with Cancel), `/tasks/{id}`, `/threads`, `/threads/{id}`, `/cockpit`, `/twin`, `/evals` (local only), `/prompts`, `/connectors` (the connectors, and the quick tools beside them: on or off, their settings; the only page without the chat beside it). The chat marks where the conversation moves to another thread (a rule with its name, a link to it; the owner's newest line, not yet filed, is taken to be in its answer's thread); the Threads page lists them (open or closed, how full) and shows one's summary, tasks and everything said in it. Web addresses in what's said, task reports, steps and thread summaries are links (`linked.tsx`). Hovering the name in the header shows what's running: the commit and how long ago it was deployed (`/api/version`, Railway's `RAILWAY_GIT_*`; lit for 10 minutes after a deploy). The look: black, JetBrains Mono to read, Silkscreen (8/12/16px only) for labels, one acid accent, amber only when the owner is needed; a state changes colour, never size (top of `styles.css`). Polls the agent's API every second; the Cockpit tab draws the live activity stream with React Flow, laid out by dagre from who calls whom, fitted to the layout's own bounds (React Flow's measurements lag new parts); parts kept in React Flow's state, or rebuilt each tick they lost their measurements and the graph vanished under steady traffic). The context twin is a part of its own: who asks the reader or hands the writer a conversation (`transcript`), and each page they open or edit (`open Uber`, `link Uber → Work`), each a call to `twin`. The map (parts, their roles, who calls whom) is kept in the browser, so a refresh starts from all of it, not just the agent's last few notices; Forget starts it afresh. Click a notice to read it in full (the agent keeps 2000 characters of each). The Context twin tab (`/twin`) draws the twin's graph with React Flow, laid out by d3-force (run to rest at once; placed nodes stay put and only new ones move, then a collide-only pass makes room; Tidy lays it all out afresh; nodes kept in React Flow's state, or a fresh node object hides until measured; each node always has a target handle, or React Flow drops its edges; the Delete key is off, deleting is the page's button). The owner edits it by hand: + Node, drag a node's grip onto another to link them, click a line to edit its relation and preview or unlink, and on a node's page rename it, add or remove aliases, edit or delete its page; edits are recorded as from the panel. Routers dashed, the open node's links lit, stale previews dashed; nodes the reader or writer opens or edits light up live (the activity stream's calls to `twin`). Small sounds (`sounds.ts`, `public/sounds/<cue>.wav`, made with earshot and chosen by the owner): presses, tabs, the owner's own scrolling, switches, messages each way, approvals, a task needing them or done, and the cockpit's tx/rx; Web Audio so a click lands with the press; "Sound on/off" in the header, kept per browser. `data-sound` on an element picks its cue, or `""` for none. Phones (≤760px, `useNarrow()`, same breakpoint in `styles.css`): one column at a time, Chat its own tab and the default, Tasks as list then detail, the cockpit graph top to bottom above the timeline. |
| `docs/protocol.md` | Device wire contract, one for every bridge (platform-specific commands marked). Change it first, then bridges and relay. |
| `docs/roadmap.md` | Milestones. Tick them off as they land. |
| `justfile` | All dev tasks. `just` lists them. |
| `.env` | `ARCHANGEL_TOKEN`, `OPENROUTER_API_KEY`, `TAVILY_API_KEY` (optional). |

## Commands

```sh
just agent            # chat in the terminal; also serves the panel API on 127.0.0.1:8765
just panel            # control panel on http://localhost:5173
just relay            # relay on :8080, reload
just reverse          # phone localhost:8080 → Mac (USB)
just bridge-install   # build, install, enable the service
just bridge-enable    # re-enable the service only
just send '<json>'    # POST a command to the phone
just screenshot       # → screenshot.jpg
just pc-send '<json>' # the same, to the PC
just pc-screenshot
just bridge-windows-test  # the Windows bridge's tests that run anywhere (CI runs the rest on Windows)
just tunnel           # ngrok, for running without the cable
just test             # all tests
just twin alex        # the context twin on a real model, in a terminal, from a made-up graph
just twin-eval        # the twin's evals on a real model (pass rates; costs a little)
just threads-eval     # the thread router's evals on a real model (pass rates; costs a little)
just logs             # bridge logcat
```

Debug builds' Dev relay defaults to `ws://localhost:8080/ws/device` and the `.env` token. Prod is the deployed relay, entered once.

## Agent

One owner, one conversation, any channel, kept as threads (one per topic, `docs/threads.md`). Everything that wakes the orchestrator is an `Event`; everything it says goes out through the gateway to an `Address`.

| File | Role |
|---|---|
| `messages.py` | `Address(channel, id)`, `Message(address, parts)`, `Part = Text \| Image`. Medium- and model-independent. |
| `models.py` | The model-library seam: `openrouter(name, timeout=120)` (only `TRUSTED` hosts, in the owner's order, each falling back to the next: an open model's cheap hosts can serve gibberish; a new model may need its host added) (a stalled call is abandoned and retried, not left blocking the one conversation; deep research gets 15 minutes) (the orchestrator reasons as little as its model allows, `think=False`: DeepSeek otherwise thinks for up to a minute a call, and everything the owner says waits behind it; no effort level or token cap bounds it. The background agents keep reasoning), `content(image)`, `prompt(parts)`, `Instructions` (string, or a callable read each run). |
| `events.py` | `Event`: `prompt()`, `reply_to`, `from_owner`, `attachments()`, `fallback(error)`. `OwnerMessage`, `TaskUpdate`, `Notice` (something a channel saw, e.g. a call went to voicemail), `Scheduled` (something due now; the owner's words, and how late if Archangel was down). `thread`: the thread it belongs in, if known. A new trigger (incoming call) is a new subclass. |
| `channels/` | `Channel`: `name`, `shows` (what it can show, listed to the orchestrator: a call can't show a picture), `owner` (the owner's address there), `start(deliver)` (the owner's messages, or a `Notice`), `send(message)`. Channels only move messages. `cli.py`: terminal, `/image <path> [text]`; only when there is one. `panel.py`: control panel channel plus its local API (transcript, tasks, steps, images, prompts, and `/api/activity`, a server-sent event stream of live activity, `/api/connectors`: the services, never their secrets, `/api/tools`: the quick tools, on or off and their settings (a secret's value never leaves; `PUT` changes one), and `/api/twin`: the graph, a node's page, links and history, and the owner's edits: nodes, names, aliases, links; `/api/schedule`: what's to come; `/api/version`: the commit running and since when); routes async (SQLite). Its buttons send owner messages. `login.py`: sign in with GitHub, the owner only; a signed session cookie; afterwards, back to the page asked for (a texted report link). `twilio.py`: the owner's texts via Twilio (`/twilio/sms`, checked against Twilio's signature, other numbers ignored); replies by Twilio's API, screenshots as a private link (UK numbers can't send pictures). Also calls (`/twilio/voice`): Twilio's ConversationRelay does speech and turn-taking, Archangel trades text with it over a WebSocket (`/twilio/voice/relay`, signed the same way); speech split at a breath (under a second apart) is joined into one thing said, so it gets one reply; after `Message.ends` (the orchestrator's `hang_up`) it ends the call once the words have had time to be spoken (Twilio doesn't say when it's done), unless the owner speaks first; on a call, everything is said on it; otherwise it rings only when asked for a call back (`report_via voice`), at most 3 times in 10 minutes, and texts after a hang-up (but not replies to what was said on that call, like "Goodbye.": `Message.answering`). Calls it makes connect at once (the message is said on pickup); answering-machine detection runs in the background, and a voicemail gets the message after the beep. How a call went (voicemail, no answer) is a `Notice` to the orchestrator, which decides what to text. `shows` says whether a call is live. |
| `web.py` | The one web server; HTTP channels add their routes to `web.app`. Local (127.0.0.1, Host-checked) unless GitHub sign-in is set; then public on `$PORT`, trusting the proxy's headers, and serving the built panel too; pages asked for at another address (Railway's own) go to the same page at the public address, so sign-in lives on one domain (not `/health` or `/twilio/`). `/health`. |
| `links.py` | Signed links that open without sign-in and expire after a day: screenshots (`/screenshots/…`), for texts (on a call, an approval's screenshot is texted this way and the call says so), and the location page. Only with a public address. |
| `location.py` | Where the owner is (the phone stays at home): `owner_location` gives the last shared place, how long ago, and a link (`/where/…`) whose page shares the browser's location once, on opening. Nothing runs on the owner's phone. The address comes from OpenStreetMap (Nominatim); it's kept in the store and arrives as a `Notice` where the link was asked from. |
| `gateway.py` | Both ways: owner messages → `OwnerMessage` events, handled concurrently; outgoing messages → the channel in their address. Records the transcript (an owner's line goes with its event, to be filed under its thread once routed; a reply carries its thread, `Message.thread`). A failing channel is logged, not raised. |
| `orchestrator.py` | The agent the owner talks to; never acts on the phone. `handle(event)`, one at a time, in the event's thread (`threads.route`, beside the twin's reader: both model calls), seeing that thread's history only; what it starts and says is filed under it. Tools: `start_task(goal, report_via?, on?)` (`on` the phone or the PC), `use_connectors(goal, report_via?)` (a background task in the owner's connected services; sees which are connected), `research(question, deep?, report_via?)` (a background task; `deep` only from the owner's own message, once they've agreed to its cost), the quick tools' functions (`tfl_status`, `weather`, `convert_currency`, `calculate`…, from `tools/`, only while on; answers inline, tried before anything else: a tool, then the web, then research, a device last), `search_web(question)` and `read_page(url)` (answers inline; read what a result only points to), `installed_apps(on?)` (what's installed, to choose between the web and an app), `answer_task` (a waiting task's answer, or the owner's word to a running one), `report_visibility(id, public?)` (says whether a report is public, or changes it; public only from the owner's own message), `redirect_task(id, channel)` ("text me when it's done"), `cancel_task`, `send(channel, text, screenshot?)`, `hang_up` (on a call, after this reply), `owner_location` (for "near me"; tasks get the address typed), `do_later(what, at? | in_minutes?, every?, report_via?)` ("in 15 minutes get me an Uber": woken with `what` when due, in this thread; `at` is the owner's local time, code does the arithmetic; `every`: cron in the owner's time, "every weekday at 7") and `cancel_later`, `remember` and `forget` (the owner's words, to the context twin's writer at once), `ask_twin`, `search_threads` and `read_thread` (another conversation thread, when the owner refers to one), `improve(request, pr?)` (Archangel changing itself, M14: a background `code` task; only from the owner's own message) and `merge(pr)` (deploys; likewise). Sees the twin's root page every turn, and, before answering anything the owner says, what the twin's reader finds bears on it (a few seconds: each page opened is a model call). Sees the time (the owner's, `Europe/London`), its thread (and what it carries on from), the other recent threads, the quick tools that are on, the channels, devices (online, offline, woken when needed; a PC that never connected isn't listed), task list (public reports marked, other threads' tasks marked) and what's scheduled every turn. Replies go to `event.reply_to`; approvals (yes or no) only when `event.from_owner`: it never decides one for the owner. |
| `tasks.py` | Runs pilots in the background, one task on each device (phone, PC) at a time, the rest queued for it; research, connector and code tasks run beside them. Briefs each new device or connectors task from the context twin first (a step shows the briefing; not research: its question goes to a web search, and the owner's life needn't); resumes waiting tasks with the owner's answer; passes what the owner says to a running one (its pilot reads it on its next step); cancels. Records each step; sends a `TaskUpdate` when a task finishes or needs the owner, answered in the thread that started it (`Task.thread`). |
| `store.py` | `data/archangel.db`: transcript (each line's thread), tasks (with `report_to`, `kind`: phone, pc, research, deep research, connectors or code, `public`: its report opens without sign-in, and `thread`) and research pages (`data/pages/`, kept) and their steps, edited prompts, connectors (settings and sign-ins, as JSON), quick tools (on or off, settings, as JSON), where the owner last shared they were, each device's latest hello (a sleeping PC is woken by the card it named), and the tables of threads (`threads/store.py`), the schedule (`schedule.py`) and the context twin (`twin/graph.py`), which own them. Images (screens, chat pictures) are files in `data/images/`, deleted after 3 days. Paused runs keep only their latest screen. |
| `prompts.py` | Every prompt by name (the pilots: "phone pilot", "pc pilot"; "thread router", "thread summariser"). Defaults live in code beside their agents; panel edits live in the store and win from the agent's next run (`Prompts.live(name)`). |
| `schedule.py` | Later (M13): `Schedule` (its own table): `add(due, what, said, report_to, thread, every?)`, `cancel`, `upcoming`, `watch(fire)` (sleeps until the next due or a change; marks each fired, or moves a repeating one to its next time (`following`, cronsim), before firing, so a crash never does it twice; whatever came due while down fires on start, once). Times absolute, shown both ways (`when`: "Wed 18 Nov 08:00, in 11 h"); `parse(at, in_minutes, every)`. No Temporal: one owner's timers are rows and a sleeping loop. |
| `coder.py` | Archangel improving itself (M14): `Coder(github(token))`: `change(request, branch, record)` starts `.github/workflows/improve.yml` (Claude Code in GitHub Actions on the owner's Claude subscription; the token a repo secret, never here), finds its run by name (`run-name` is the branch), follows it, and reads its `result` artifact: the PR and a summary, or a question's answer; `branch(pr)` to carry a PR on; `merge(pr)` (squash). The request, run and PR are public. |
| `history.py` | Context trimming: last 2 screenshots; the last 100 messages (cut at turn starts) only as a backstop: a thread is carried on in a new one at its size in tokens first. |
| `threads/` | Threads (M18, `docs/threads.md`): the conversation kept per topic. `Threads.route(event)`: an owner's message goes where the router (`router.py`, the quick model, no reasoning: every message waits for it, beside the twin's reader) chooses, an earlier thread (reopened if closed; it searches the rest, `search_threads`) or a new one; a task's update to the thread that started it (or what carried it on); a notice to the latest. Never fails (the latest, if routing breaks), and marks the thread said in at once, so a summary written meanwhile can't close it (a summary closes only a thread nothing was said in since it was read; a failed one is retried an hour later). The router sees where the conversation is apart from the others (a model took the highest number for the newest). A thread the owner wraps up (a thanks that asks nothing) closes once answered; one quiet 3 h closes too; each is summarised as it closes (`summariser.py`, the main model, in the background; again if said more in after). One whose context reaches 30k tokens (`FULL`, from the last call's usage) is carried on in a new thread at once, starting from its summary (written in the background). `store.py`: each thread's history, state and an FTS5 index; adopts the conversation from before threads in one transaction ("Before threads": its last 40 messages, and every transcript line and task until then). |
| `instructions.md` | Orchestrator prompt. |
| `logs.py` | `logs/<time>/agent.log` at DEBUG (`logs/latest` → newest, last 20 kept). `logs.run(agent, …)` logs each tool call, result and invalid call. |
| `activity.py` | Live activity for the cockpit, announced like logging: `hop(target, kind, text)`, `call(...)` for a request and its reply. Request, task and actor ids ride in context variables, so nothing passes them along. Roles are declared at the source (`declare(name, role)` for channels; agent runs and calls declare the rest), so the cockpit hard-codes no names. Never waits or raises; a slow listener misses notices; nothing is stored. |
| `research.py` | The web, never the phone: `search` and `read` (Tavily search and extract: results with sources, or a page as text, in seconds; the orchestrator answers from them; both `service` calls in the cockpit) and `research` (Perplexity's Pro Search, `sonar-pro-search`, via OpenRouter: under a minute, ~3p, sources listed; `deep`: Sonar Deep Research, ~4 minutes, ~60p, an 80k-character essay whatever it's told). |
| `reports.py` | The reporter: topic and material in, `Report(tldr, title, pages)` out (the main model, a few pence); the model writes the pages, the layout is fixed: a cover (title, tldr, date), then portrait pages like a PDF's, phone-shaped (9:16), wide tables scrolling inside, in the panel's look with system fonts (the page may load nothing). Reports are saved as finished HTML: a new style applies to new ones. A research task's report is its link (`/reports/{id}`, on the panel's site, behind sign-in unless made public (`Task.public`; `Web.share` opens it), with a CSP that lets nothing in it run or load) and the tldr, which the orchestrator texts; what research found is a step. |
| `connectors.py` | The owner's online services as MCP servers (`pydantic_ai.mcp.MCPToolset`), added and signed in to from the panel. Hosted ones (Notion; Slack with the owner's own Slack app; any other) sign in through the MCP SDK's `OAuthClientProvider` (dynamic registration where allowed, afresh at each sign-in: an old one may be revoked or name an old address; it refreshes tokens; the owner comes back to `/connectors/callback`, with the issuer (`iss`, RFC 9207: the SDK rejects a code without it when the server advertises it, as Notion does)). Gmail and Calendar: Archangel signs in to Google itself and runs `workspace-mcp` (`uvx`, stdio) on that sign-in. Tools are prefixed with the connector's name; read-only ones (MCP `readOnlyHint`) run at once, the rest raise `ApprovalRequired`. Each call is a `service` call in the cockpit, the connector its own part. One that won't connect drops out of the run and shows "needs sign-in". One connector per account, in a profile ("work", "personal"); the agents see them by profile and choose. Each has its own settings (a work Google client may live in the company's Google Cloud); each Google account runs its own workspace-mcp, on its own credentials folder, only for the length of a run (`keep_alive=False`: FastMCP's default left one running after every task, ~260 MB each). |
| `tools/` | Quick tools (M15): live data the orchestrator answers from inline, no device. `tool.py`: `Tool` (ABC: `name`, `title`, `about` (one line, for the owner and the orchestrator's list), `settings` (`Setting(key, label, secret?, required?)`), `functions()` (async, return text; their names are the orchestrator's tool names and their docstrings its description, so say what each is for and not for), `setting(key)`, `get(url, **params)`), `ToolError` (a message the model acts on). `__init__.py`: `Tools(store, client?, kinds=BUILT_IN)`: `BUILT_IN` lists the tools (add one: subclass `Tool`, list it; the panel shows it by itself); `all()` and `configure(name, enabled?, settings?)` for the panel; `active` (on, and every required setting set; on by default); `describe()` (the orchestrator's list each turn); `toolset` (what the orchestrator gets: only active tools' functions; each call a `service` call in the cockpit, a source that fails answered as "isn't answering: try the web", never raised). Owner's state is the store's `tools` table. Built in, all free and keyless: `tfl.py` (line status and why, journeys (an unclear place resolves to the best match, said), arrivals at a stop or station; optional `app_key` setting), `weather.py` (Open-Meteo: now, hourly, days, sunrise and sunset; optional default `place`), `currency.py` (Frankfurter), `dates.py` (the time anywhere, UK bank holidays, days between, exact arithmetic with an AST evaluator that accepts only numbers and operators), `places.py` (Open-Meteo geocoding, shared). |
| `twin/` | The context twin (M12, `docs/twin.md`): the owner's second brain. `graph.py`: `Graph`, nodes with markdown pages (an empty page is a router), linked with a relation and a few-word preview; `open(name)` is what a model reads at a node. Keeps what models can't be trusted to: one node per name or alias (any case), every edit recorded with the owner's words and where they were said, previews made stale by a page change found (`stale()`). `You` is the root. `reader.py`: the reader agent (the orchestrator's quick model, no reasoning: every message and task waits for it), read-only: starts at the root (given, no call), opens only what the task needs by its previews, says only what bears on it, or nothing. `writer.py`: the writer agent, an episode in, graph edits (usually none) and a line for the owner out; can't finish with a stale preview; pages in markdown. `Twin` (`__init__.py`): `root()` (in the orchestrator's prompt every turn), `hear(said)` (before the orchestrator answers each owner message), `brief(goal)` (before each phone or connectors task; "" if the reader fails), `tools` (`ask_twin`, for the orchestrator, pilot and helper mid-task); reads each conversation once it's been quiet 10 minutes (from the transcript, so the owner's answers to tasks are in it; marked, so read once, and the transcript before the twin isn't), and `remember` at once; one episode at a time. What it noted reaches the orchestrator as a `Notice` (to sms rather than a call), which tells the owner. |
| `evals_tab.py` | The panel's Evals tab, on a local agent only (never public): lists the twin's eval runs (`evals/twin/results/`), returns one, and starts one (`evals.twin.run` in its own process, writing its file as runs finish). The tab: runs with pass rates, a case-by-run grid with the change since the run before, and one run opened: what went in, every check (and the judge's reason), the reader's answer, the writer's edits as before/after, and the graph it ended with (added, changed and read nodes marked; click one for its page against how it started). |
| `helper.py` | Sub-agent for connector tasks: the goal and the connected services' tools in, a short answer out. Pauses for approvals and `ask_owner`, resumably, like the pilot. |
| `runs.py` | What the pilot and helper share: `Outcome`, the owner's `Answer`, `Record`, and turning a paused run's requests and the owner's answer into results. |
| `devices/pilot.py` | The device sub-agent, shared by every device: act → screenshot → decide. `Pilot(model, Kit(device, vision, guard, investigator), Platform)`; a `Platform` (`phone.py`, `pc.py`) brings the tools, prompt and tidying up. Shared tools: `open_app`, `look`, `second_opinion` (the investigator), `ask_owner`; and the twin's `ask_twin`. Ends with `done` or `give_up`. No rules for stuck: it judges its own progress, asks for a second opinion or gives up; 120 steps is only a runaway backstop. It notes findings as it goes (old screens are forgotten). Pauses (resumably) as `needs_approval` or `needs_answer`. What a run changed (a faked location, an unlocked PC) is put back when it ends or pauses. |
| `devices/phone.py` | The phone's tools: `close_app` (launch, recents, swipe its card up, home: no model guesswork), `tap(target, hold?)`, `type_text`, `scroll`, `press` (keys, and `unlock`: a swipe up past a lock screen without a PIN), `set_location` (fakes the phone's GPS, only for apps that just use it, "near me"). `done` goes home, unless `leave_open`. Prompt `phone.md`. |
| `devices/pc.py` | The PC's tools: `click(target, button?, double?)`, `type_text` (at the cursor; line breaks never submit), `scroll(direction, within?)` (the wheel, over a described area), `press(keys)` (a key or chord; all but moving around and selecting are checked like a click), `unlock` (the bridge types the PIN it keeps; locked again when the run ends or pauses). Prompt `pc.md`. |
| `devices/guard.py` | Checks every tap or click (and consequential keys) with a separate model call; anything that sends, pays, logs in, deletes or changes settings pauses for approval (a search's filters aren't settings). It sees everything the owner has said to the task (kept by `tasks.py`, in memory), so what they've agreed to isn't asked again. Fails closed. |
| `devices/investigator.py` | The fallback model reads the last 3 screens and recent steps when the pilot asks for a second opinion: what's in the way, how past it. Also explains stuck reports. |
| `devices/vision.py` | Finds things on the screen: `Vision.find(screen, target) → Box \| None`. `JevVision` (TypeSafe Jev via OpenRouter decisions API), `ModelVision` (any vision model), `FallbackVision` (the fallback vision model on a miss or failure). |
| `devices/relay.py` | `Device(client, platform)`: a device through the relay, whichever of its platform is connected (`android`, `windows`). Positions are screen fractions, turned into pixels with the latest screenshot's size (so rotation is fine); screenshots JPEG, the phone's half-scale at quality 30 (Jev rejects WebP; 30 locates as well as 80), the PC's about 1600 wide at 60 (desktop text is small). Offline (503): waits up to 60 s, then resends; a PC it knows the network card of is woken by the phone (Wake-on-LAN) and waited for 150 s. Lost mid-command (502): resends only read-only commands. Each hello is kept in the store. |

The pilot never handles coordinates: it describes what to tap, vision finds the box, the centre gets tapped.

| Connectors | Not env: entered on the panel's Connectors page and kept in the store. Slack needs an internal Slack app with the same redirect URL. |
| `TAVILY_API_KEY` | unset: no quick web search (deep research still works). Free tier: 1,000 searches a month. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `ARCHANGEL_OWNER` | unset: the panel is local. Set (a GitHub OAuth App, and your GitHub username): public, sign-in required. |
| `GITHUB_TOKEN` | unset: Archangel can't improve itself. Set: a fine-grained token for this repo only (Actions, Contents, Pull requests: read and write). The workflow also needs the repo secret `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`). |

Errors: a failed task (phone offline, stuck, model misbehaving) is a task update; the orchestrator retries once or tells the owner. Only orchestrator failures reach the owner raw, via `event.fallback(error)`. Tools get 3 retries for invalid calls. Model API errors (429, 5xx, network) are retried by Pydantic AI's OpenRouter client (it uses the `openai` package as its HTTP client; every call goes to OpenRouter).

Human-in-the-loop: the pilot pauses via Pydantic AI deferred tools (`ApprovalRequired` from the guard, `CallDeferred` from `ask_owner`). The paused run is saved with the task, so an answer works even after a restart. Tasks running at shutdown come back `interrupted`, and at startup each is reported where it was due (the orchestrator may retry it).

**Investigating a run:** the task's steps and screens in the control panel, then `tail -100 apps/agent/logs/latest/agent.log`. `jev` lines show Jev's raw answers (noul, box, confidence).

Tests use `FunctionModel` and `httpx.MockTransport`; no API calls. The context twin also has evals on a real model (`apps/agent/evals/twin/`): a made-up owner's graph (`graphs/alex.toml`; never the real owner's), cases in `cases.toml` (reader: what it must and mustn't say, how much it opens; writer: what it keeps or leaves alone; checked in code where possible, by a model judge otherwise), each run 3 times for a pass rate; every run saved to `results/` (ignored). The panel's Evals tab (local) runs them and shows each run. `just twin` is the same twin by hand: `hear`, `brief`, `ask`, `say`, `show`, `review` (a model judges the whole graph against the design), `save` a grown graph as a fixture. The thread router has them too (`apps/agent/evals/threads/`, `just threads-eval`): a made-up owner's past threads and what they say next, the thread it should go in, checked in code. Shared fakes in `tests/fakes.py` (`fakes.threads(store)`: real threads with a router that carries on the latest, as one conversation did); the `store` fixture is a fresh store in a temp dir.
Jev gotcha: through OpenRouter, images must be `{"type": "image_url", "image_url": {"url": "data:…"}}` in `state`; TypeSafe's `assets` format is silently ignored.
New channel = one `Channel` subclass registered in `__main__.py`; the orchestrator only sees its name ("via telegram") and can route to it. Images in replies (approval screenshots) must be shown by the channel; the CLI saves them to a temp file and prints the path.

## Android bridge

Flat package `tech.arrakis.archangel.bridge`.

| File | Role |
|---|---|
| `BridgeService` | AccessibilityService. Owns the connection while enabled. No foreground service needed. |
| `Connection` | OkHttp WebSocket. 15 s pings, 1–30 s jittered backoff, early retry on network return. `Connection.status`. |
| `CommandExecutor` | Decode, run serially, never throw. Replays replies for repeated ids (last 64). |
| `Device` / `AndroidDevice` | Phone capabilities behind an interface; executor tests run on the JVM. |
| `WakeOnLan` | `wake`: a magic packet broadcast on the phone's network, waking the PC. |
| `MockLocation` | `location`: test providers for GPS, network and fused, resent every second; removed on `location` without coordinates or when the service stops. Needs the bridge chosen as the mock location app (a button on its screen opens Developer options). |
| `Protocol` | Wire types. |
| `Config` / `ConfigStore` | Dev and Prod relays (URL and token each), which is on, and the device name. One SharedPreferences value; a tap switches. |
| `MainActivity` | One Compose screen: status, config, settings shortcuts. |

The service declares itself an accessibility tool (`isAccessibilityTool`): otherwise Android hides "data sensitive" windows like permission prompts from it and silently drops its taps there.

minSdk 30, targetSdk 36, compileSdk 37, JDK 17. Versions in `gradle/libs.versions.toml`. Release builds: `wss://` only, no baked-in URL or token.

## Windows bridge

`apps/bridge-windows/`, package `bridge`, the Android bridge's shape in Python: `protocol.py`, `executor.py` (serial, never raises, replays the last 64 ids), `device.py`/`windows.py` (the PC behind an interface; tests use a fake), `connection.py` (15 s pings, 1–30 s jittered backoff), `config.py` (Dev and Prod relays, name, PIN; one JSON file in `C:\ProgramData\Archangel`, readable only by administrators and SYSTEM, the PIN DPAPI-encrypted for the machine). Windows-only: `win32.py` (GDI capture, `SendInput`, the input desktop, processes as the signed-in user), `uia.py` (UI Automation tree), `service.py`, `settings.py` (tkinter window; Save installs and starts the service).

The lock screen and administrator prompts are the `Winlogon` desktop, which only SYSTEM can open, and a service (session 0) has no screen. So the service starts the bridge as SYSTEM in the console session and keeps it there (restarted when the session changes or it exits); before each command its input thread moves onto whichever desktop has input. Apps it opens and the Start menu it lists are the signed-in user's (`WTSQueryUserToken`). `unlock` types the PIN as keys, Enter only if still locked (never into an unlocked desktop).

PyInstaller folder build (`--onedir`): a one-file exe runs the app as a child process, which a service can't be. CI (`.github/workflows/bridge-windows.yml`, on a Windows runner) runs every test on its real desktop, builds, runs the exe against the relay in the foreground and as the service, and publishes `archangel-bridge.zip` to the `bridge-windows` release from `main`.

## Conventions

- Small, flat, obvious. Deep modules, small interfaces (Ousterhout). No abstraction until needed.
- Agent follows 12-Factor Agents: own the prompt, context and control flow.
- Defaults over config. New env vars need a real reason.
- Comments say *why*, not *what*.
- Caller-facing errors use codes from `docs/protocol.md`. The bridge must never crash: Android disables crashing accessibility services.
- Update README.md, this file and `docs/` in the same commit as the change. Short, direct.
- **This repo is public. Nothing about the owner's real life goes in it, anywhere:** code, tests, evals, fixtures, docs, roadmap, commit messages, PRs. No real names (friends, family, the owner's), places, devices, accounts, groups, purchases, numbers or anything else from conversations, the twin or prod. Make it up (Sam, Priya, Tom; Ofcom's `+447700900xxx` numbers), even when quoting something the owner said. Check the diff for it before every commit.

## Limits

- `FLAG_SECURE` screens (banking, payments) screenshot black; `ui_tree` usually still works.
- Some apps detect accessibility services or ignore synthetic input.
- The phone has no SIM: no texts or calls on it. The orchestrator prompt says so (edit it there if that changes).
- Can't pass a secure lock screen. Unattended: no lock, "Stay awake while charging", battery optimisation off.
- Browser-sideloaded on Android 13+: App info → ⋮ → "Allow restricted settings" before enabling. `adb install` unaffected.
- Install or force-stop switches the service off.
- `type` uses `ACTION_SET_TEXT`; editors that reject it (X's compose box) get a clipboard paste instead, which overwrites the clipboard.
- The guard is a model judging a screenshot: strong, not perfect. It adds one model call per tap.
- The control panel's buttons are messages to the orchestrator, so approving from it costs one model call.
- A waiting task doesn't hold the phone; if another task runs meanwhile, the approved tap re-locates its target on whatever screen is there.
- Android rate-limits screenshots; the bridge retries briefly.
- The PC: its primary display only. Someone using it while a task runs shares the mouse and keyboard with the pilot. Typing goes as characters, so an app that only reads keys (some games, remote desktops) misses it. A window running as administrator can't be clicked without the service. A UAC prompt for a standard account (a password) isn't handled. Ctrl+Alt+Del can't be sent, so a PC that demands it to sign in can't be unlocked. Waking needs Wake-on-LAN set up and, usually, a wired connection; the phone must be on the same network.
- A faked location can be seen through (apps reading Wi-Fi or cell location, or checking for mock locations), and Uber or banking apps may flag it: the pilot types an address wherever an app takes one.
